Design system · internal reference

Motion Lab

Every motion primitive the Transpahire marketing site is allowed to use, on one page. If an animation is not demonstrated here, it does not exist in the system — add it here first, then use it.

This page is noindex and is not linked from the public site. Its job is to make the system falsifiable: a primitive that looks wrong here is wrong everywhere, and a primitive nobody can find a use for on this page should be deleted.

1 · Reveal

motion.css § 1

Entrance on scroll. One attribute per element, five variants. Distance scales with the size of the object: a line of type moves 16px, a dashboard moves 64px. Everything decelerates — nothing eases in.

Fade

data-reveal="fade"

Opacity only. The safe default inside an already-transformed parent.

Fade Up

data-reveal="up"

The workhorse. Used for roughly 80% of reveals on the site.

Fade Down

data-reveal="down"

Only for elements that belong above their trigger — a dropdown, a banner.

Slide Left

data-reveal="left"

Paired with "right" across a two-column segment so the halves converge.

Slide Right

data-reveal="right"

Never on narrow viewports where it would imply horizontal overflow.

Scale Reveal

data-reveal="scale"

0.94 → 1. For a self-contained panel that should read as arriving whole.

Fade + Blur

data-reveal="blur"

Expensive to composite and visually loud. One per view, headlines only.

Rise

data-reveal="rise"

The product-composition entrance: 64px, slower settle, slight scale.

4b · Product primitives — P1 … P5

motion.css § 4b

The primitives the product compositions use. Each is here because it is used: P1 by nine compositions, P2 by the section 06 sequence and by the mission console, P3 by section 08 and by section 07's payoff, P4 by the skill graph, P5 by the homepage hero. If one of them ever stops being used, it should be deleted rather than kept for symmetry.

P5 was added in Phase 4 and re-hosted in Phase 5, and it is documented as a composition of two existing primitives rather than as a fifth animation — see the bottom of this section for why that distinction is worth making.

P1 · Meter fill

Communicates: this quantity has a magnitude relative to a whole. scaleX from a left origin over 620ms on --ease-entrance, so it is transform-only. The value is a unitless --meter-v fraction, and with JavaScript unavailable the bar renders at its true width immediately — the value is the content, not a decoration of it.

P2 · Sequenced reveal with per-beat offsets

Communicates: these parts assemble in this order, and this part is separate. data-layers gives a fixed 120ms cadence; a sequence needs specific beats, because the pauses are the information. Below, the fourth item is deliberately alone: it arrives 600ms after the third and 400ms before the fifth, and the gap is doing all the work.

data-beat takes the storyboard's own absolute number rather than an offset from the previous beat, so editing one beat cannot shift every beat after it. --beat-delay inherits, which is how a meter or an SVG path inside a beat picks up that beat's timing without being told separately. Under reduced motion the whole stack is present immediately.

P3 · List reorder

Communicates: your priorities changed the answer. This is the one animation on the site that is the information rather than a decoration of it — the movement is what tells you the ranking responded. A FLIP: measure, put the rows in their new order, transform them back to where they were, release. 320ms on --ease-standard, and nothing animates a layout property.

No absolute positioning, so the list keeps its own height and nothing below it moves. Under reduced motion the DOM is reordered with no transform at all, which repositions instantly — the new order is the information and it survives; only the movement is dropped.

P4 · Path draw documented exception

Communicates: these two things are connected, and here is the connection. Used once, by the skill-relationship graph in section 07.

This is the one place the site animates a property outside the transform / opacity / filter allowlist. stroke-dashoffset is not in it, and there is no transform that draws a line along itself. The exception is bounded: six paths maximum on a page, this primitive only, short simple paths only. Section 07 draws one.

The dash offset is measured from the path's own length at run time, not authored: the geometry is responsive, so an authored length would be wrong at every width but one. With no JavaScript, or under reduced motion, the line is simply there — a relationship the reader cannot see is a relationship the page did not state.

P5 · Drawer reveal composed, not new

Communicates: a row is selected, and the view opens into it. Used once, by the homepage hero, where the list gives you a number and the drawer gives you the argument — which is the site's whole thesis in one frame.

Updated in Phase 5, not replaced. The composition it belongs to was rebuilt — the drawer is inset to 42% rather than 22%, and it is tabbed — but the animation is byte-for-byte the one Phase 4 shipped. That is the test of whether P5 was documented correctly: a composition changing shape should not move the motion system, and it did not.

Why it is not a fifth animation. It composes two things the site already had: the nav drawer's translate-and-fade, and the tp-panel-in entrance. There is no new keyframe and no new module — the trigger is an ancestor's reveal, exactly like P1's meter fill, so with JavaScript unavailable the drawer is simply there. A primitive that is really two primitives pointed at one composition should be documented as that, or the system grows a new entry every time an existing pair gets a new job.

Cap: one per page, enforced by tools/check.mjs. A page with two drawers sliding in has an animation, not a statement. And the hero is allowed to run it above the fold because it is a one-shot entrance on load that finishes inside --dur-medium, not an interaction — there is deliberately no click-to-open behaviour in the hero.

4c · P6 — Staged layers

motion.css § 4b · scene.js

P6 · the score, taken apart. Added in Phase 6 for the landing page's signature (prototypes/STAGE-3.md § 8). Six layers of one object on a sticky stage, and the scroll is the clock: --p runs 0 → 1 across a stage --scene-length viewports tall; the layers arrive and leave in non-overlapping windows at 0.14 · 0.31 · 0.48 · 0.65 · 0.82, and the rail says where you are. Only transform and opacity move.

Two clocks, one number. Where the browser supports a view() scroll timeline, CSS drives --p itself and scene.js keeps only the rail and data-state; everywhere else one passive scroll listener writes it. The timeline has to hard-code the header inset (view(block 64px 0px)) because it cannot read a token, so tools/check.mjs asserts that number equals --header-h, and tools/audit.mjs asserts the two clocks agree at eighteen scroll positions.

Cap: one per page, enforced by tools/check.mjs. The stack is the base. Under reduced motion, below 700px wide or 620px tall, or without JavaScript, the same six layers stack in reading order with sticky captions — nothing hidden, nothing microscopic. 5 · Utility

motion.css § 5

Component state transitions. Each is driven by a JS module that owns the accessibility contract — roles, keyboard, focus — and delegates all visual movement to CSS.

Tabs

Roving tabindex, arrow keys, Home / End, aria-selected, panels toggled with the real hidden attribute. Try it with the keyboard.

The incoming panel fades up 8px over 320ms. No height animation: the frame is a fixed aspect ratio, so there is nothing to reflow and nothing to shift.

Arrow keys move between tabs and activate them. Home and End jump to the ends. Only the selected tab is in the page tab order, so a keyboard user tabs past the whole group in one press.

The Myniq reference has the same visual pattern with none of this behind it. Borrowing the interaction idea and rebuilding the implementation is the whole thesis of this phase.

Accordion

Height animates with grid-template-rows: 0fr → 1fr: no JS measurement, no max-height guesswork, no jump when the content reflows at a different breakpoint.

A div with tabindex="0" — what the Myniq export uses — announces nothing to a screen reader and cannot be operated with Space. A button gets the role, the state, and both keys for free.

Rotates 180°, driven purely by the data-open attribute on the item. It is decorative and hidden from assistive technology — aria-expanded on the button is what actually conveys state.
